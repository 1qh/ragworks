# A redistributable RAG benchmark

Four shapes, three failure mechanisms, every document generated by a script in `shapes/` — so the corpus carries no third-party or confidential material and anyone may redistribute it.

Each shape ships with the **control** that proves the mechanism is the cause rather than the arrangement. A measurement without its control is not a result: eleven further shapes were authored, measured, and refused, because a shape that does not reproduce its failure teaches the wrong lesson to everyone who runs it.

## The shapes

| Shape                  | Mechanism                                             | Generator                         | Control                                                  | Score             |
| ---------------------- | ----------------------------------------------------- | --------------------------------- | -------------------------------------------------------- | ----------------- |
| Scanned decision       | extraction wipe-out                                   | `scan-degenerate.ts`              | its own source text, 612 chars against a 1-char scan     | artifact property |
| Scanned discount table | extraction misalignment                               | `table-multilevel.ts` + `scan.ts` | the born-digital page, answers at rank 1                 | artifact property |
| Dense two-header grid  | retrieval collapse                                    | `dense-2hdr.ts`                   | the ruled variant — parse correct, still fails           | 1 of 2 questions  |
| Windowed band table    | generation reads the right band from the wrong window | `band-twodim.ts`                  | `band-first.ts`, same bands without the second dimension | 5 of 5 questions  |

Every generator exports `QUESTIONS`, each carrying `expect` and the `reject` distractor the question turns on. Run a stack against those, not against questions of your own — see _The entry is a question_ below.

## What each one measures

**Extraction wipe-out.** The page is rendered, rotated, blurred, speckled and JPEG-compressed, then given a text layer of exactly ONE character. That character is deliberate: a PDF with no text layer is obviously OCR-work, while a PDF with one character is a text layer a parser will happily “succeed” against and recover nothing from. A stack that answers is reading pixels; one that does not is trusting a text layer that is not there.

**Extraction misalignment.** The same multi-level discount table answers at gold rank 1 born-digital and fails once scanned. Structure held constant, only the extraction path varied — so the difficulty is the arrangement PLUS the parse that loses it. What a flattened read destroys is specific and was reached by refutation: a header that SPANS several columns and sits adjacent to none of its cells. Every coordinate written against the thing it labels survives a scan, which is why a section header spanning rows answered, and why an English price grid answered on both paths.

**Retrieval collapse.** The one worth the most and the hardest to author. It reproduces BORN-DIGITAL with a perfect text layer, so the difficulty is not optical and anyone running it measures their retriever rather than their OCR. It survives whole-table chunking, every granularity a block-bound chunker offers, and a perfectly correct parse — the ruled control proves the last of those, with every column carrying its own group header and the gold still never retrieved.

Its difficulty is a CONJUNCTION, established by varying both factors independently:

|                      | one header row  | two header rows                       |
| -------------------- | --------------- | ------------------------------------- |
| **distinct cells**   | answers, rank 1 | answers, rank 1                       |
| **look-alike cells** | answers, rank 4 | **reproduces** — gold never retrieved |

Neither factor does anything alone. A deep header gives the read an alignment to get wrong; look-alike cells remove any downstream chance of noticing that it did, because a figure an order of magnitude out is not a plausible answer while a percentage one point out is. So the authoring gate is cheap: a candidate is worth building only if it carries both.

**Generation.** The first three all fail before the model sees the answer. A stack can be strong at extraction and strong at retrieval and still hand back the wrong row, and nothing in those three measures it. The windowed band table does: its gold is often retrieved at rank 1 and the model returns the right distance band read from the wrong time window.

## The entry is a QUESTION, not a page

Measured, and it corrects the obvious reading of the table above: on the dense grid, one question is never retrieved while a SIBLING CELL on the same page is answered at rank 2. Same page, same parse, same chunks, opposite outcome. So “this page defeats the pipeline” is too strong and the honest unit is the question-plus-page pair. Use the questions each generator exports; substituting another cell can silently turn a hard entry into an easy one and make the corpus look broken.

The windowed band table carries five questions and reproduces on all five — but the STAGE differs by cell, so one page teaches a different thing per question:

| window      | band        | gold | distractor | gold rank     | stage      |
| ----------- | ----------- | ---- | ---------- | ------------- | ---------- |
| 10:00–15:59 | 2–20 km     | 1.3  | 1.8        | 1             | generation |
| 16:00–18:59 | 20–50 km    | 2.5  | 1.5        | not retrieved | retrieval  |
| 16:00–18:59 | 50–100 km   | 2.8  | 2.4        | 4             | generation |
| 19:00–23:59 | 50–100 km   | 2.0  | 2.8        | 3             | generation |
| 06:00–09:59 | over 100 km | 2.7  | 1.9        | not retrieved | retrieval  |

Every gold is UNIQUE in the grid. That is an authoring constraint rather than a detail: several values repeat across cells, and a repeated gold makes a correct-looking answer unattributable to the cell asked about.

## Grading: a recital is not an answer

A `contains` check is not sufficient. An answer reciting EVERY candidate value contains the gold while demonstrating no disambiguation — `either 2.8, 2.4, or 2.0` is the exact shape three of the five band questions produce. Each question names the distractor it turns on; **an answer stating the distractor is not grounded, whatever else it says.**

Implement that rule, do not merely document it. In this corpus’s own history the rule was written down and absent from the probe applying it: the probe computed whether the answer took the distractor, printed it on screen, and keyed its verdict on grounding alone. Two questions were reported as answered while the line directly above the verdict said the distractor was taken.

## A benchmark entry has a shelf life, and it differs by mechanism

- **extraction** shapes are properties of the ARTIFACT — a one-character text layer defeats a text-layer parser for as long as that is what it is, and no model improvement changes it;
- **retrieval** shapes are properties of the CORPUS and the retriever, and survive a better generator;
- **generation** shapes are properties of the MODEL, and a model release can retire one silently.

A fifth shape — a fee table with a clause overriding three of its rows, isolated by three arms — was published and is now RETIRED: re-measured after the answering model changed, it answers every question at gold rank 1. Its generator stays in `shapes/twohop.ts` as evidence, and out of the table above.

So record the model a generation entry was measured against, and re-measure when it changes. Otherwise a stack scoring full marks looks like it beat a hard shape when the shape had simply ceased to exist.

## The cache trap, for anyone re-measuring after a fix

A content-addressed pipeline keys a stage by the document bytes plus config plus engine version, so an application-code change moves none of them and the same PDF returns the same stored parse however many times a correct fix ships. Three successive deployments of a real parser fix produced byte-identical output and read as the fix failing. Change one character in the page, regenerate, and the difference appears at once. A cache hit still records lineage, so a fresh timestamp on the artifact proves a run happened and NOT that any work did.

## Reproduce

```ts
import { build, QUESTIONS } from './shapes/band-twodim.ts'
await Bun.write('band-twodim.pdf', build())
```

Every generator is deterministic — the scan degradation uses a seeded generator rather than a global random source, so two people running the corpus measure the same document rather than comparing scores across two different ones. Verify with the text-layer helper:

```ts
import { textLayerOf } from './shapes/pdf.ts'
textLayerOf(build()).length // 700 for the windowed band table, 1 for either scan
```
